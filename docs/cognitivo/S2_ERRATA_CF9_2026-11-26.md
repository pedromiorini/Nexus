# Errata CF9 — `patch apply` não mapeia para `APPLY_PATCH` (2026-11-26)

O texto antigo não é reescrito. O passo 5, o critério CF9-outcome e o conjunto D em `docs/cognitivo/AUDITORIA_2026-10-22.md` (commit `c187c12548af1e5a84d21431286b2ae8c22ead40`, linhas 512, 554 e 562 na base `01d98868db455cf8f426a52fc5cdf95054c4392b`) continuam como foram escritos. Esta errata os substitui só no ponto `patch apply`.

**Antes, nesses três pontos:** o fallback de tokens mapeia `patch apply` para `APPLY_PATCH`, junto com `apply patch`.

**Agora:** `patch apply` não mapeia. `veto_key("patch apply")` é `PATCH_APPLY` e `veto_key("APPLY_PATCH")` é `APPLY_PATCH`. O fallback de tokens só devolve o nome da tabela quando as duas chaves são iguais (alternativa 1 do pré-registro S2). `apply patch`, `apply_patch` e `APPLY_PATCH` seguem no passo 1 (`_normalize_action_key` já é chave de `ACTION_EFFECTS`) e continuam mapeando para `APPLY_PATCH`.
